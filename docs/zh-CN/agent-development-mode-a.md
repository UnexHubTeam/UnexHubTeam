面向 Agent 开发者 · 模式 A / Unexhub 容器

更新日期：2026-10-23

模式 A 使用你提供的 OCI 镜像，为每次用户会话启动独立的应用容器。开发者在部署配置中选择管理员提供的**实例类型**；用户启动时选择运行时间，核对费用后点击启动。运行到期或主动停止后，容器释放，临时文件随会话清理。

需要 Cloudflare 容器时，请使用[模式 B 指南](agent-development-upload.md)。两种模式的实例名称、CPU、内存和小时价格均以平台当前目录为准，不能按旧截图或示例价格推算实际账单。

<a id="section-1"></a>
## 1. 开始前准备什么

- 可编辑 Agent 的开发者账号。
- 能在 `linux/amd64` 上运行的单个 OCI 镜像，镜像同时提供应用网页与后端 API。
- 可用的完整镜像地址，以及私有镜像仓库需要的只读拉取凭据。
- 已测量的 CPU、内存、临时磁盘和启动时间，供选择实例类型。
- 应用使用数据库时，明确所需 PostgreSQL/MySQL 版本；见[数据库配置指南](agent-databases.md)。

<a id="section-2"></a>
## 2. 选择应用交付方式

当前仅开放 **单容器（前后端同镜像）**：一个镜像包含网页和 API，前端优先使用同源相对地址访问后端。

**前后端分容器**和**纯前端 + 后端容器**目前均已隐藏并禁用，不能用于新启动。已有这两种配置的 Agent，需要先重新校验单容器镜像后再启动；已有实例仍可访问和停止。不要通过接口自行绕过界面限制。

模式 A 当前不提供容器目录挂载配置，也不提供 GPU、自定义 CPU/内存/磁盘输入。原有资源输入已从界面隐藏，请使用实例类型目录选择资源。**空闲自动关闭（分钟）**默认 15，设置 0 可关闭。保存后对新启动实例生效；连续空闲达到该时长会释放容器及临时文件。系统会保守检查连接、CPU、网络和任务状态，活跃请求和长连接会延后释放；用户选择的最长运行时间仍独立生效。

<a id="section-3"></a>
## 3. 准备镜像与运行配置

| 项目 | 要求 |
| --- | --- |
| 架构 | `linux/amd64` OCI 镜像 |
| 监听 | 在 `0.0.0.0` 监听配置端口；端口在 `1024–65535` 内，例如 `8080` |
| 健康检查 | 提供以 `/` 开头的轻量路径，例如 `/health`，不要在探针中调用模型 |
| 启动命令 | 可选；留空使用镜像默认 `ENTRYPOINT` / `CMD`，填写后覆盖默认命令 |
| 主进程 | 保持前台运行，处理 SIGTERM，并及时关闭请求和数据库连接 |
| 环境变量 | 只填写非敏感应用配置；`UNEX_` 为平台保留前缀 |
| 文件 | 视为临时文件，不依赖宿主目录、Docker socket 或特权模式 |
| 日志 | 记录阶段和脱敏错误；不记录密码、Key、数据库 URI 或完整授权信息 |

例如：

```dockerfile
FROM python:3.14-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8080
CMD ["python", "app.py"]
```

示例不代表平台要求使用 Python。其他语言只要满足镜像与运行约定均可使用。`EXPOSE` 不能代替应用实际监听。

<a id="section-4"></a>
## 4. 上传与校验镜像

1. 构建并推送一个具有固定版本标签的镜像。不要将 `.env`、个人模型 Key、Registry 密码或数据库密码打入镜像。
2. 在 **部署配置 → 模式 A · Unexhub 容器 → 镜像来源** 中选择可用入口。若平台提供 Docker Push 地址，按页面生成的命令推送；外部 Registry 则填写完整镜像地址。
3. 私有仓库使用平台的 Registry 凭证管理功能，选择仅有拉取权限的凭据。不要把仓库密码放进应用环境变量。
4. 点击镜像校验，等待 digest 和安全扫描结果。需要平台副本的镜像，按页面提示等待复制完成。
5. 核对绑定的是本次发布的镜像，避免复用旧版本的校验状态。

镜像首次启动可能需要下载，等待时间取决于镜像体积和仓库连通性。没有可用镜像或仓库授权失败时，启动失败并显示错误；不要将私有镜像改成公共镜像来绕过凭据问题。

<a id="section-5"></a>
## 5. 选择实例类型与数据库

在 **最小资源要求 → 实例类型** 中选择平台提供的规格。下拉选项显示名称、CPU、内存与小时价格。两种模式维护各自的目录，切换模式会重新查询，模式 A 的配置不能直接替代模式 B 的资源选项。

模式 A 初始目录参考 `lite`、`basic`、`standard-1` 到 `standard-4`；管理员可以调整名称、资源、价格或停用规格，**页面实际目录优先**。不要把实例标识当作永不变化的资源保证。

需要数据库时，在同一卡片的 **数据库配置** 中添加 PostgreSQL、MySQL 或二者，选择版本后保存。启动容器时连接变量自动注入后端，例如 `UNEX_DATABASE_POSTGRESQL_URL`、`UNEX_DATABASE_MYSQL_HOST`；完整变量和可运行示例见[数据库配置指南](agent-databases.md)。不需要数据库可留空。

数据库密码由后端读取，不可返回浏览器、写日志或放入前端构建。停止容器不会自动清空独立数据库。

<a id="section-6"></a>
## 6. 用户启动、时长与费用

1. 用户打开 Agent，平台检查是否已有可继续使用的实例。
2. 没有活跃实例时，确认开发者设置的实例类型，并选择可用的运行时间。
3. 页面显示估价，用户确认后点击 **启动**。平台拉取所需镜像并启动容器。
4. 等待运行就绪后，通过平台提供的打开入口使用应用。
5. 到达选择的运行时间后自动停止，也可以提前主动停止。点击停止后立即显示停止动画；等待实际资源清理完成后，页面更新最终状态和账单。

算力费按平台展示的**小时单价 × 计费时长**计算，时长向上取整到小时。启动时按所选最长时长预扣充值余额；停止后依据实际运行时间结算，多余预扣退回。准备/创建阶段不计入成功运行时长，启动失败不产生成功运行费用。大模型调用费用单独按平台规则计入。

管理员修改价格后，已启动实例继续按启动时的价格结算；新启动使用最新可用价格。被停用的规格不能再创建新实例。账单以平台返回的估价与最终结算为准。

模式 A 的容器链接采用 `/?session=<会话ID>`。实例就绪后，同一链接可在其他电脑或新浏览器直接打开。缺少 session 返回 `{"error":"missing_session"}`；session 错误或实例未就绪、已停止、已过期时返回 `{"error":"session_not_ready"}`。不同浏览器的应用登录状态相互独立。

<a id="section-7"></a>
## 7. 在本机验证

```bash
docker buildx build --platform linux/amd64 -t registry.example.com/team/my-agent:1.0.0 --load .
docker run --rm -p 8080:8080 registry.example.com/team/my-agent:1.0.0
curl --fail http://127.0.0.1:8080/health
```

确认首页、业务 API、流式输出、数据库连接以及进程停止都可用。私有仓库先在本机验证拉取权限，但不要将登录配置复制到镜像内。

<a id="section-8"></a>
## 8. 开发者自测与发布

保存镜像与运行配置后，在部署配置「最小资源要求」下方找到「开发者自测」，点击「前往启动页面」；也可从算力配置前往启动确认页。选择时间、核对估价并创建测试实例。至少验证一次冷启动、页面访问、业务请求、数据库读写、主动停止和到期停止。

镜像绑定与扫描完成后，按页面提示提交审核。镜像有漏洞时应先了解风险并修复；页面风险确认不代替实际运行自测。上架后用户使用已审核的配置，修改镜像或运行契约应按页面提示新建版本并重新审核。

自测实例启动后，展开「技术信息」即可在右侧查看容器运行日志。日志仅向该 Agent 的开发者本人、且由本人启动的自测实例开放；展开时自动获取最近输出，可暂停或跟随最新日志。收起、隐藏页面或实例停止后不再自动获取。普通用户使用时不会出现此窗口。

<a id="section-9"></a>
## 9. 常见问题

| 现象 | 检查 |
| --- | --- |
| 实例类型为空或不可用 | 重新加载目录，确认管理员未停用规格 |
| 私有镜像无法拉取 | 完整地址、digest、仓库可达性及只读凭证是否正确 |
| 启动后打不开 | 应用监听 `0.0.0.0`、端口一致、健康路径有效，查看脱敏日志 |
| 数据库连接失败 | 已选择数据库、读取注入变量、版本和 TLS 设置正确 |
| 停止后文件消失 | 容器文件为临时数据；使用数据库或及时导出 |
| 分容器不能选择 | 当前暂未开放，使用单容器方式 |
| 空闲关闭未立即执行 | 检查活动连接、CPU、网络或后台任务；连接保活和采样可能延后释放 |
| 看到旧 GPU/整机字段的截图 | 截图可能来自旧版，以当前实例类型与费用确认表单为准 |

<a id="section-10"></a>
## 10. 发布检查

- 当前 digest 与已测试制品一致，镜像扫描已完成。
- 选择正确的实例类型，核对资源和实际小时价格。
- 只交付一个应用镜像，未依赖目录挂载，并验证空闲关闭与最长运行时间设置。
- 数据库配置、变量读取和不同用户的数据隔离验证通过。
- 冷启动、停止、到期释放、页面与 API 调用已验证。
- 镜像、前端、日志和错误消息中没有平台管理凭据或私有仓库密码。
- 面向使用者说明临时文件、最长运行时间和算力费。
